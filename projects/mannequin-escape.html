This was the first project where I applied SOLID and clean C# from the start. The game manager, inventory and enemy AI became foundations I have reused since.

Enemies that sense, remember and forget

Each enemy carries a perception component made of separate senses: sight, hearing (a noise system the player triggers) and hit. Every sense is its own component that answers one question: can I sense this stimulus right now?

The shared base class handles the rest. When a stimulus is lost, a short memory timer starts before the enemy forgets it, so a player who ducks behind a wall for a second is still hunted. The perception component then picks the strongest current target and raises an event.

The enemy state machine listens to that event and moves between idle, patrol, chase and attack. Frozen and ragdoll states handle traps and energy-wave hits.

public class SightSense : SenseComponent
{
    [SerializeField] private float sightDistance = 20f;
    [SerializeField] private float sightHalfAngle = 45f;
    [SerializeField] private float eyeHeight = 1.5f;

    protected override bool IsStimuliSensable(PerceptionStimuli stimuli)
    {
        Vector3 toStimuli = stimuli.transform.position - transform.position;

        // 1. Close enough?
        if (toStimuli.magnitude > sightDistance) return false;

        // 2. Inside the view cone?
        Vector3 dir = toStimuli.normalized;
        if (Vector3.Angle(transform.forward, dir) > sightHalfAngle) return false;

        // 3. Nothing blocking the line of sight?
        Vector3 eye = transform.position + Vector3.up * eyeHeight;
        if (Physics.Raycast(eye, dir, out RaycastHit hit, sightDistance)
            && hit.collider.gameObject != stimuli.gameObject)
            return false;

        return true;
    }
}

Where the patterns live

Template method
SenseComponent runs the sense, remember and forget loop; each sense only overrides IsStimuliSensable.
Composite
PerceptionComponent combines any number of senses into one target.
Observer
Senses, perception and the state machine talk through C# events, so none of them reference each other directly.
State
Enemy states (idle, patrol, chase, attack, frozen, ragdoll) and the player's environment-interaction states.
MVC
Inventory model, UI controller and slot views are separate, with drag-and-drop and tooltips on the view side.
Component and strategy
Behaviour is assembled from small interchangeable components in the inspector.

Character and procedural animation

I modelled, rigged and animated the mannequin in Blender, then brought it into Unity.

On top of the baked animation, a second state machine drives two-bone IK on the arms. When the character walks past an object, it finds the closest point on the surface from its shoulder. If that point is within reach, the arm rises, touches the surface and returns to its pose. It is a small detail, and it made the mannequin feel aware of the space around it.
